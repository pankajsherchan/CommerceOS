CommerceOS Unit 08A

Jenkins pipeline, explained step by step

This guide explains the Jenkinsfile that verifies the repository, builds Docker images, and publishes the storefront and commerce API images to dev ECR repositories.

Sections

Big Picture Helper Functions Pipeline Settings Parameters Stages Image Tags Not Included

1. Big Picture

The Unit 08A Jenkinsfile is an artifact publishing pipeline. It proves the codebase can pass checks, build production images, and push those images to ECR. It does not deploy the images to ECS.

Beginner translation: Jenkins is acting like a repeatable release workstation. It checks the code, builds the images, labels them, and uploads them to AWS.

2. Helper Functions

The Jenkinsfile starts with small Groovy helper functions so the main pipeline stages stay readable.

validateRequiredParam

def validateRequiredParam(String name) {
  if (!params[name]?.trim()) {
    error("${name} is required")
  }
}

This checks that a required Jenkins parameter is not blank. If it is blank, the build stops with a clear error before any expensive work runs.

loginToEcr

aws ecr get-login-password --region '${region}' |
  docker login --username AWS --password-stdin '${registry}'

This gets a temporary ECR login password from AWS CLI and passes it to Docker. After that, Docker can push images to that ECR registry.

pushImageTags

This pushes the tags Jenkins created for one repository. It always pushes immutable SHA/build tags and conditionally pushes the moving latest-style tag.

3. Pipeline Settings

pipeline {
  agent any

  options {
    buildDiscarder(logRotator(numToKeepStr: '20'))
    disableConcurrentBuilds()
    skipDefaultCheckout(true)
    timestamps()
  }

  environment {
    DOCKER_BUILDKIT = '1'
  }
}
  • agent any lets Jenkins choose any compatible agent. That agent must have Git, Docker, AWS CLI, Terraform, pnpm, and uv installed.
  • buildDiscarder keeps the most recent 20 builds so old logs do not grow forever.
  • disableConcurrentBuilds prevents two runs of this job from publishing overlapping image tags at the same time.
  • skipDefaultCheckout means the pipeline controls checkout explicitly in its first stage.
  • timestamps adds timestamps to logs, which helps when debugging slow builds.
  • DOCKER_BUILDKIT=1 enables Docker BuildKit, which the Dockerfiles use for dependency cache mounts.

4. Parameters

Jenkins parameters let the same pipeline run against the dev ECR repositories without hardcoding AWS account-specific values.

Parameter What it does
AWS_REGION The AWS region containing the ECR repositories.
STOREFRONT_ECR_REPOSITORY_URL The full ECR repository URL for the storefront image.
COMMERCE_API_ECR_REPOSITORY_URL The full ECR repository URL for the commerce API image.
IMAGE_TAG_PREFIX The environment or channel prefix for tags. It defaults to dev.
AWS_CREDENTIALS_ID Optional Jenkins AWS credential ID. Leave it blank when the Jenkins agent already has an IAM role.
PUSH_DEV_LATEST When enabled, also pushes a moving <prefix>-latest tag.

5. Pipeline Stages

1

Checkout

Jenkins checks out the repository, reads the current commit SHA with git rev-parse --short=12 HEAD, and builds the image tag names from the tag prefix, commit SHA, and Jenkins build number.

2

Validate Inputs

The pipeline fails early if required values are missing: region, storefront ECR URL, API ECR URL, and tag prefix. It also checks that the tag prefix is valid for Docker tags.

3

Storefront Verification

Jenkins runs the frontend checks from apps/storefront: install dependencies, lint, typecheck, run tests, and build the Next.js app.

4

Commerce API Verification

Jenkins runs backend checks from services/commerce-api: sync dev dependencies, run pytest, and import the FastAPI app as a boot smoke test.

5

Terraform Static Verification

Jenkins checks Terraform formatting, initializes the dev environment with -backend=false, and validates the configuration. This confirms the Terraform code is structurally valid without touching remote state.

6

Build Images

Jenkins builds the storefront image from apps/storefront and the API image from services/commerce-api. Each build receives the immutable tags and, when enabled, a moving latest-style tag.

7

Push Images

Jenkins extracts the ECR registry host from each repository URL, logs Docker into each unique registry, then pushes all tags for both images.

8

Post Success Message

On success, Jenkins prints the combined immutable tag so the image version is easy to find in the logs.

6. Image Tags

Each image gets multiple tags so humans and automation can refer to the same build in different ways.

Tag Example Purpose
<prefix>-<short-sha> dev-a1b2c3d4e5f6 Links the image to a Git commit.
<prefix>-build-<number> dev-build-42 Links the image to a Jenkins build.
<prefix>-<short-sha>-b<number> dev-a1b2c3d4e5f6-b42 Combines Git and Jenkins identity in one immutable tag.
<prefix>-latest dev-latest Convenience tag that moves with each successful run when enabled.
Why immutable tags matter: ECS deployment work can later point to a specific build and avoid ambiguity about which code is running.

7. Not Included In Unit 08A

This pipeline intentionally stops after image publishing. These tasks belong to later work:

  • Terraform remote state setup.
  • Terraform plan or apply against AWS.
  • ECS service deployment or task count changes.
  • Database migrations.
  • Dev ALB smoke tests.
  • Keycloak or auth verification.
